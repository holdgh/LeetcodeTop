## 分析与解决

从缓存数据能清晰看到核心问题：**DeepSeek 驱动的检索助手在多轮工具调用后，频繁发起「无 query 参数的空搜索请求」**，导致工具报错，最终引发 JSON 解码失败。以下是具体分析和根治方案：

### 一、报错根源拆解（从数据看因果链）
1. **关键异常点**：检索助手多次返回 `{"type": "tool_use", "name": "search", "input": {}}`（`input` 为空，无 `query` 参数）；
2. **工具报错反馈**：系统返回 `MaintenanceDocRetriever.search() missing 1 required positional argument: 'query'`（明确告知需要 `query` 参数）；
3. **模型无视报错**：即使收到工具的参数缺失报错，检索助手仍继续发起空参数请求，最终输出无效内容（如仅含空格的文本+空工具调用），导致后续 JSON 解析失败；
4. **与千问的差异**：千问能严格遵循工具调用的参数要求，不会在收到参数缺失提示后重复犯错，而 DeepSeek 对「工具调用参数约束」的记忆和执行能力较弱。

简单说：DeepSeek 在多轮对话中“忘记”了 `search` 工具必须传入 `query` 参数，即使工具明确报错，仍持续发起空请求，最终导致整个流程崩溃。

### 二、为什么多轮后才出现？
1. **上下文过载**：多轮对话中，工具调用记录、报错信息不断累积，超出 DeepSeek 对“参数约束”的记忆范围，逐渐偏离正确调用格式；
2. **提示词约束不足**：原提示词可能仅说明“可以调用 search 工具”，但未明确“必须传入 query 参数”“参数缺失时如何处理”；
3. **错误反馈未被有效利用**：工具返回的参数缺失报错，没有被提示词明确要求“修正参数后重新调用”，导致模型无视报错重复犯错。

### 三、根治方案（从“约束+容错+拦截”三层解决）
#### 1. 强化提示词：明确工具调用的“硬约束”（核心）
修改检索助手的 `sys_prompt`，强制要求「必须传参+报错后修正」，示例：
```python
retriever_sys_prompt = """
你是设备运维检索专家，仅处理当前会话的用户问题，严格遵循以下规则：
1. 调用工具前必须检查参数：
   - 调用 "search" 工具时，**必须传入 "query" 参数**（字符串类型，非空、非空格），否则绝对不能发起调用；
   - 若用户问题信息不足，先通过追问用户补充关键信息（如设备型号、故障场景），再调用工具。

2. 处理工具返回结果：
   - 若工具返回 "missing 1 required positional argument: 'query'"，说明你未传 query 参数，需立即补充 query 后重新调用；
   - 若工具返回无相关结果，可调整 query 关键词（如扩展为“冷却系统维护 安全操作 断电要求”），最多重试2次，仍无结果则停止调用。

3. 输出格式要求：
   - 仅返回工具调用结构或文本说明，不包含任何无效字符；
   - 工具调用必须包含 "type": "tool_use"、"name": "search"、"input": {"query": "具体关键词"}，三者缺一不可。

4. 禁止行为：
   - 禁止在无 query 参数的情况下调用 "search" 工具；
   - 禁止连续3次以上调用工具（避免死循环）；
   - 禁止返回仅含空格、空字符串的无效内容。
"""
```
- 核心：用“必须”“绝对不能”等强语气明确约束，同时给出参数缺失时的处理步骤（补充参数而非重复空调用）。

#### 2. 工具层拦截：拒绝空参数调用（容错）
在 `search` 工具的封装中添加参数校验，提前拦截空参数请求，避免报错传递：
```python
@tool
def search(query: str) -> List[str]:
    """检索运维手册，必须传入非空的 query 参数"""
    # 参数校验：拒绝空字符串、纯空格
    if not query or query.strip() == "":
        return ["Error: 检索关键词不能为空，请提供具体查询内容"]
    # 原有检索逻辑
    return doc_retriever.search(query.strip(), top_k=3)
```
- 效果：即使模型发起空参数调用，工具也返回明确的友好提示，而非 Python 原生报错，帮助模型快速修正。

#### 3.  Agent 层限制：防止工具调用死循环（兜底）
在检索助手 Agent 中添加「工具调用次数限制」，避免模型反复发起无效调用：
```python
class AgentPair:
    def _create_retriever_agent(self) -> ReActAgent:
        # 新增：记录工具调用次数，避免死循环
        tool_call_count = 0
        max_tool_calls = 3  # 最多调用3次工具
        
        def check_tool_call_limit():
            nonlocal tool_call_count
            tool_call_count += 1
            if tool_call_count > max_tool_calls:
                raise Exception("工具调用次数已达上限，停止调用")
            return True
        
        model = DashScopeChatModel(...)
        return ReActAgent(
            name="检索助手",
            sys_prompt=retriever_sys_prompt,
            model=model,
            tools=[
                Tool(
                    func=search,
                    name="search",
                    description="检索运维手册，必须传入非空的 query 参数（如“冷却系统维护 断电”）"
                )
            ],
            # 新增：调用工具前执行次数检查
            pre_tool_use=lambda tool_name, input_args: check_tool_call_limit(),
            finish_function_name="retrieve_finish"
        )
```
- 说明：`pre_tool_use` 是 AgentScope 中 Agent 的钩子函数，调用工具前执行，返回 False 或抛出异常则终止调用，避免模型无限次空调用。

#### 4. 清理无效输出：过滤空内容（最终兜底）
在检索助手的输出处理中，过滤仅含空格、空字符串的无效内容：
```python
# 在获取检索助手回复后，添加输出清理
retriever_reply = await retriever.reply()
# 清理文本内容中的纯空格、空字符串
if isinstance(retriever_reply.content, list):
    cleaned_content = []
    for item in retriever_reply.content:
        if item.get("type") == "text":
            text = item.get("text", "").strip()
            if text:  # 仅保留非空文本
                cleaned_content.append({"type": "text", "text": text})
        elif item.get("type") == "tool_use" and item.get("input", {}).get("query"):
            # 仅保留含有效 query 的工具调用
            cleaned_content.append(item)
    retriever_reply.content = cleaned_content
# 将清理后的回复传给专家 Agent
await expert.memory.add(retriever_reply)
```
- 效果：即使模型返回无效内容，也会被提前过滤，避免干扰后续 JSON 解析。

### 四、总结
问题本质是 **DeepSeek 模型对工具调用参数的约束遵循度不足**，多轮对话后易“遗忘”必填参数要求。解决方案的核心是：
1. 用强约束提示词明确“必须传参”和“报错修正步骤”；
2. 工具层+Agent 层双重拦截，拒绝空参数和死循环调用；
3. 清理无效输出，避免解析报错。

按此方案修改后，检索助手将不再发起空参数调用，工具报错会被正确处理，多轮对话的稳定性会显著提升。
