RESTful API 基于 HTTP 协议定义了一组标准化的请求方法（HTTP Methods），每种方法对应资源的不同操作方式。以下是常见的请求方式及其作用、特性与典型应用场景：

---

### **1. GET**
- **作用**：**获取资源**（查询数据）。
- **特性**：
  - **安全**（Safe）：不会修改服务器资源。
  - **幂等**（Idempotent）：多次请求返回相同结果。
- **应用场景**：
  - 查询用户列表：`GET /users`
  - 获取单个用户详情：`GET /users/{id}`
- **响应**：通常返回 `200 OK`（成功）或 `404 Not Found`（资源不存在）。

---

### **2. POST**
- **作用**：**创建新资源**（提交数据）。
- **特性**：
  - **非安全**：会修改服务器资源。
  - **非幂等**：多次请求可能创建多个资源。
- **应用场景**：
  - 新建用户：`POST /users`（请求体包含用户数据）。
  - 提交表单数据或触发非幂等操作（如支付）。
- **响应**：通常返回 `201 Created`（成功创建）或 `400 Bad Request`（请求无效）。

---

### **3. PUT**
- **作用**：**完整更新资源**（替换整个资源）。
- **特性**：
  - **非安全**：会修改服务器资源。
  - **幂等**：多次更新效果与单次相同。
- **应用场景**：
  - 全量更新用户信息：`PUT /users/{id}`（请求体包含完整新数据）。
  - 若资源不存在，可设计为创建资源（需服务端支持）。
- **响应**：通常返回 `200 OK`（更新成功）或 `204 No Content`。

---

### **4. DELETE**
- **作用**：**删除资源**。
- **特性**：
  - **非安全**：会修改服务器资源。
  - **幂等**：多次删除结果相同（资源已不存在）。
- **应用场景**：
  - 删除用户：`DELETE /users/{id}`。
- **响应**：通常返回 `200 OK`（删除成功）或 `404 Not Found`（资源不存在）。

---

### **5. PATCH**
- **作用**：**部分更新资源**（仅修改指定字段）。
- **特性**：
  - **非安全**：修改资源。
  - **幂等性依赖实现**（建议设计为幂等）。
- **应用场景**：
  - 修改用户邮箱：`PATCH /users/{id}`（请求体仅包含 `email` 字段）。
- **响应**：通常返回 `200 OK` 或 `204 No Content`。

---

### **6. HEAD**
- **作用**：**获取资源的元数据**（如响应头），不返回响应体。
- **特性**：
  - **安全且幂等**。
- **应用场景**：
  - 检查资源是否存在：`HEAD /files/{filename}`。
  - 验证缓存有效性（通过 `ETag` 或 `Last-Modified` 头）。

---

### **7. OPTIONS**
- **作用**：**获取资源支持的 HTTP 方法列表**。
- **特性**：
  - **安全且幂等**。
- **应用场景**：
  - 跨域请求预检（CORS Preflight）：浏览器自动发送 `OPTIONS` 请求，检查允许的方法。
  - 查看 API 支持的操作：`OPTIONS /users` 返回 `Allow: GET, POST, HEAD`。

---

### **8. 其他方法（较少使用）**
| 方法        | 作用                      | 常见场景                |
|-------------|--------------------------|-----------------------|
| **TRACE**   | 回显客户端请求（用于调试）  | 诊断请求处理路径        |
| **CONNECT** | 建立隧道连接（如 HTTPS）   | 代理服务器与 SSL 通信   |

---

### **核心原则与设计规范**
1. **资源导向**：URI 表示资源（名词），HTTP 方法表示动作（动词）。  
   - ✅ 正确：`DELETE /articles/123`（删除文章）。  
   - ❌ 错误：`POST /articles/123/delete`（动作混入 URI）。

2. **幂等性与安全性**：  
   - **幂等**：GET、PUT、DELETE、HEAD、OPTIONS。  
   - **安全**：GET、HEAD、OPTIONS。

3. **状态码语义化**：通过 HTTP 状态码明确结果（如 `404` 表示资源不存在，而非 `200` 返回错误消息）。

---

### **实际应用示例**
```http
# 创建订单
POST /orders
Body: { "product": "book", "quantity": 2 }

# 查询订单列表
GET /orders

# 更新订单地址（部分更新）
PATCH /orders/456
Body: { "address": "New York" }

# 删除订单
DELETE /orders/456
```

---

通过遵循 RESTful 设计原则，API 可具备清晰的语义、高可读性和易于维护性，是现代 Web 服务开发的通用标准。
