在系统嵌入外部页面且共享用户体系时，实现跳转免登录的常见方案如下：

### 一、Token 验证方案
1. **URL Token 传递**
   - 流程：系统A生成带时效的加密Token拼接到跳转URL→系统B解密验证Token→创建本地会话
   - 关键点：需HTTPS保障安全，推荐HMAC动态签名+时间戳防重放

2. **POST 表单自动提交**
   - 流程：系统A生成包含Token的隐藏表单→通过JavaScript自动提交到系统B→后端验证
   - 优势：避免URL暴露Token，适合敏感场景

### 二、标准化协议方案
3. **OAuth2.0 授权**
   - 流程：系统B作为Client，跳转时携带授权码→向授权服务器换取Access Token→完成登录
   - 特点：符合行业标准，适合对外开放API的场景

4. **JWT 方案**
   - 实现：系统A用HS256/RSA256生成签名Token→通过URL参数/Header传递→系统B验签后解析用户信息
   - 注意：需严格管理签名密钥，建议加入jti防重放

### 三、企业级方案
5. **CAS 单点登录**
   - 流程：访问系统B时重定向到CAS→检查已有全局TGC→自动签发ST票据→完成免登
   - 适用场景：存在统一认证中心的企业内网

6. **SAML 协议**
   - 流程：系统A生成SAML断言→通过浏览器POST到系统B→SP验证断言有效性
   - 特点：适合跨安全域的企业级集成，常见于SaaS系统对接

### 四、补充方案
7. **跨域Cookie同步**
   - 实现：设置同根域名（如sso.example.com）→通过CORS共享认证Cookie
   - 限制：要求域名有共同父级，需配置SameSite=None+Secure

8. **后端会话同步**
   - 流程：系统A通过API将sessionID传给系统B→系统B反向查询用户数据
   - 要求：双方系统需建立信任关系，并开放内部API

### 安全增强措施
- **时效控制**：Token有效期建议≤5分钟，JWT需设置exp声明
- **防重放攻击**：使用一次性Nonce或自增序列号校验
- **传输安全**：必须强制HTTPS，敏感参数禁止明码传输
- **日志审计**：记录所有Token发放和验证记录，保留6个月以上

### 方案选型建议
| 场景特点 | 推荐方案 |
|---------|---------|
| 简单快速对接 | URL Token + HTTPS |
| 对外开放API | OAuth2.0 + PKCE |
| 企业内部系统 | CAS + 反向代理 |
| 跨组织联邦认证 | SAML 2.0 |
| 微服务架构 | JWT + API网关 |

实际落地时建议采用组合方案，例如：对外用OAuth2.0保证开放性，内部微服务用JWT提升性能，关键业务系统用SAML实现强安全认证。同时建议在跳转过程中增加二次安全确认环节（如企业微信扫码确认），避免URL被恶意构造导致的自动登录风险。
