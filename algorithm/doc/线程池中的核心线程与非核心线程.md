线程池中的核心线程与非核心线程通过以下方式区分：

---

### **1. 定义与创建条件**
| **类型**       | **核心线程（Core Threads）**               | **非核心线程（Non-Core Threads）**       |
|----------------|--------------------------------------------|------------------------------------------|
| **创建条件**   | 线程池初始化时预先创建（默认不活跃，需任务触发） | 当任务队列已满且核心线程繁忙时临时创建    |
| **数量限制**   | 由 `corePoolSize` 参数固定                 | 总数不超过 `maximumPoolSize - corePoolSize` |

**示例**：  
- 若 `corePoolSize=5`，`maximumPoolSize=10`，则核心线程最多5个，非核心线程最多5个。

---

### **2. 生命周期管理**
| **特性**       | **核心线程**                                | **非核心线程**                            |
|----------------|--------------------------------------------|------------------------------------------|
| **空闲回收**   | 默认不回收（即使长期空闲）                   | 空闲时间超过 `keepAliveTime` 后自动销毁    |
| **回收控制**   | 可通过 `allowCoreThreadTimeOut(true)` 允许回收 | 强制回收，无法常驻                        |

**Java 示例**：  
```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5,  // corePoolSize
    10, // maximumPoolSize
    60, TimeUnit.SECONDS, // keepAliveTime（非核心线程空闲60秒后回收）
    new LinkedBlockingQueue<>(100)
);

// 允许核心线程空闲超时回收（默认false）
executor.allowCoreThreadTimeOut(true);
```

---

### **3. 任务处理优先级**
| **阶段**               | **行为**                                                                 |
|------------------------|-------------------------------------------------------------------------|
| **任务提交时**         | 优先使用核心线程处理任务                                                 |
| **核心线程繁忙时**     | 任务进入队列等待                                                         |
| **队列已满时**         | 创建非核心线程处理任务，直至达到 `maximumPoolSize`                       |
| **线程池满载时**       | 触发拒绝策略（如抛出异常、丢弃任务）                                     |

**流程图**：  
```
新任务 → 核心线程是否空闲？ → 是 → 立即执行  
           ↓ 否  
       任务入队 → 队列是否满？ → 否 → 等待执行  
                       ↓ 是  
                   创建非核心线程 → 是否超过最大线程数？ → 否 → 执行任务  
                                       ↓ 是  
                                   触发拒绝策略
```

---

### **4. 配置建议**
#### **(1) 核心线程数 (`corePoolSize`)**  
- **CPU 密集型任务**：设为 `CPU 核心数 + 1`（如 8 核 CPU 设为 9）。  
- **I/O 密集型任务**：可设为 `2 * CPU 核心数`，或根据系统负载调整。

#### **(2) 最大线程数 (`maximumPoolSize`)**  
- 根据任务队列容量和系统资源设置，一般不超过 `核心线程数 * 4`。  
- **示例**：若任务突发量高且允许短暂资源过载，可适当调大。

#### **(3) 存活时间 (`keepAliveTime`)**  
- 非核心线程空闲回收时间，通常设为 30-60 秒。  
- **过短**：频繁创建/销毁线程，增加开销。  
- **过长**：闲置线程占用资源。

---

### **5. 实际场景示例**
#### **场景 1：Web 服务器处理请求**
- **配置**：`corePoolSize=50`, `maximumPoolSize=200`, `keepAliveTime=30s`  
- **行为**：  
  - 常规流量由 50 个核心线程处理。  
  - 流量突增时，任务进入队列；队列满后扩容至 200 线程。  
  - 流量回落时，非核心线程在 30 秒空闲后被回收，保留 50 核心线程。

#### **场景 2：批量数据处理**
- **配置**：`corePoolSize=CPU核心数`, `maximumPoolSize=CPU核心数`, 队列无限大  
- **行为**：  
  - 固定使用核心线程处理任务，避免线程切换开销。  
  - 适用于严格限制并发量的 CPU 密集型任务。

---

### **6. 总结**
| **维度**         | **核心线程**                          | **非核心线程**                        |
|------------------|---------------------------------------|---------------------------------------|
| **存在意义**     | 常驻线程，保障基础并发能力             | 临时扩展线程，应对突发负载             |
| **资源占用**     | 长期占用系统资源                       | 按需创建，空闲时释放                   |
| **适用场景**     | 稳态负载、低延迟任务                   | 流量波动、可容忍短暂延迟的任务         |

合理配置核心线程与非核心线程，可平衡 **资源利用率** 与 **系统稳定性**，是高并发编程的关键优化点。
