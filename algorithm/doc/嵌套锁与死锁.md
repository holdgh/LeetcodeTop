### **嵌套锁与死锁现象详解**

#### **1. 嵌套锁（Nested Lock）**
**定义**：  
当一个线程在持有某个锁的情况下，再次请求同一把锁（可重入锁）或另一把锁时，形成嵌套锁结构。

**特点**：
- **可重入锁（Reentrant Lock）**：允许同一线程多次获取同一把锁（如Python的`threading.RLock`）。
- **非可重入锁**：同一线程重复获取会阻塞自身（如`threading.Lock`）。

**示例（可重入锁）**：
```python
from threading import RLock

lock = RLock()

def func1():
    with lock:  # 第一次获取锁
        print("In func1")
        func2()  # 嵌套调用

def func2():
    with lock:  # 第二次获取同一把锁（可重入）
        print("In func2")

func1()  # 正常执行
```

**风险**：  
即使使用可重入锁，若嵌套请求**不同锁**，仍可能导致死锁。

---

#### **2. 死锁（Deadlock）**
**定义**：  
多个线程因互相持有对方所需的锁而无限阻塞，无法继续执行。

**死锁的四个必要条件**（全部满足才会发生）：
1. **互斥条件**：资源一次只能被一个线程占用。
2. **占有并等待**：线程持有至少一个资源，同时等待其他资源。
3. **非抢占条件**：已分配的资源不能被强制剥夺。
4. **循环等待**：多个线程形成环形等待链（如T1等T2，T2等T1）。

**经典死锁示例**：
```python
from threading import Lock

lockA = Lock()
lockB = Lock()

def thread1():
    with lockA:
        print("Thread1 got lockA")
        with lockB:  # 等待lockB（但lockB被thread2持有）
            print("Thread1 got both locks")

def thread2():
    with lockB:
        print("Thread2 got lockB")
        with lockA:  # 等待lockA（但lockA被thread1持有）
            print("Thread2 got both locks")

# 启动线程
t1 = threading.Thread(target=thread1)
t2 = threading.Thread(target=thread2)
t1.start(); t2.start()
t1.join(); t2.join()  # 程序卡死，无输出
```

---

### **3. 死锁的解决方案**
#### **(1) 锁顺序一致性**
强制所有线程按**固定顺序**获取锁（如先锁A再锁B）：
```python
def thread1():
    with lockA:
        with lockB:  # 按顺序获取
            print("Thread1 got both locks")

def thread2():
    with lockA:      # 同样先请求lockA
        with lockB:
            print("Thread2 got both locks")
```

#### **(2) 超时机制**
为锁设置超时时间，避免无限等待：
```python
def thread1():
    if lockA.acquire(timeout=1):  # 1秒超时
        try:
            if lockB.acquire(timeout=1):
                print("Success")
            else:
                lockA.release()  # 释放已获得的锁
        finally:
            lockA.release()
```

#### **(3) 使用上下文管理器**
通过`contextlib.ExitStack`管理多个锁：
```python
from contextlib import ExitStack

def thread_safe_operation():
    with ExitStack() as stack:
        stack.enter_context(lockA)
        stack.enter_context(lockB)  # 自动处理获取/释放顺序
        print("Locks acquired")
```

#### **(4) 死锁检测与恢复**
- **工具监控**：使用`threading.enumerate()`检查线程状态。
- **设计模式**：银行家算法（资源分配前预判安全性）。

---

### **4. 预防死锁的最佳实践**
1. **最小化锁粒度**：仅锁必要资源，缩短持有时间。
2. **避免嵌套锁**：尽量单层锁，或用更高级同步原语（如`Queue`）。
3. **使用可重入锁**：同一线程内避免自锁。
4. **单元测试**：模拟高并发场景验证锁行为。

### **总结**
- **嵌套锁**：合理使用可重入锁可避免自锁，但需警惕跨锁死锁。
- **死锁**：本质是资源竞争导致的循环等待，通过顺序一致性、超时机制等预防。
