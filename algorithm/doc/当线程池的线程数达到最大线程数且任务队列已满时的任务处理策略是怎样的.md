当线程池的线程数达到最大线程数且任务队列已满时，线程池会根据预设的**拒绝策略（Rejection Policy）**处理新提交的任务。以下是常见的拒绝策略、应用场景及代码示例（以 Python 的 `concurrent.futures` 和 Java 的 `ThreadPoolExecutor` 为例）：

---

### **一、常见的拒绝策略**

| **策略**                  | **行为**                                                                 | **适用场景**                                                                 |
|---------------------------|-------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| **AbortPolicy**           | 直接抛出 `RejectedExecutionException` 异常                              | 需要快速失败并显式处理溢出的场景（如关键任务不允许静默丢弃）。               |
| **DiscardPolicy**         | 静默丢弃新任务，不通知调用者                                            | 容忍任务丢失的非关键场景（如日志记录、统计数据上报）。                       |
| **DiscardOldestPolicy**   | 丢弃队列中最旧的任务，然后重试提交新任务                                | 优先处理最新任务的场景（如实时消息处理，旧数据可丢弃）。                     |
| **CallerRunsPolicy**      | 由提交任务的线程直接执行该任务（而非线程池线程）                         | 需要限流或避免任务丢失的场景（如生产者消费者模型，防止生产者被阻塞）。       |
| **自定义策略**            | 实现自定义逻辑（如记录日志、降级处理、存入数据库等）                     | 需要特殊处理的业务场景（如任务持久化、优雅降级）。                           |

### **二、代码示例**

#### **1. Python 的 `ThreadPoolExecutor`**
Python 的线程池通过 `concurrent.futures` 实现，但标准库未直接提供拒绝策略配置。需通过队列大小和手动检查模拟：

```python
from concurrent.futures import ThreadPoolExecutor, Future
import queue

def task(n):
    print(f"执行任务 {n}")

# 自定义拒绝策略：记录日志并抛出异常
def rejection_handler(task, executor):
    print(f"任务被拒绝：{task}")
    raise RuntimeError("线程池和队列已满")

# 创建线程池（最大2线程，队列容量1）
executor = ThreadPoolExecutor(
    max_workers=2,
    # 通过队列大小限制（需手动处理拒绝逻辑）
)

# 模拟任务提交与拒绝
try:
    for i in range(4):
        future = executor.submit(task, i)
        if future._state == "FINISHED" and not future.done():  # 检查是否被拒绝
            rejection_handler(i, executor)
except RuntimeError as e:
    print(e)

executor.shutdown()
```

#### **2. Java 的 `ThreadPoolExecutor`**
Java 的线程池直接支持拒绝策略配置：

```java
import java.util.concurrent.*;

public class RejectionPolicyDemo {
    public static void main(String[] args) {
        // 创建线程池（核心2线程，最大4线程，队列容量2）
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
            2,  // corePoolSize
            4,  // maximumPoolSize
            60, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(2),  // 任务队列容量
            new ThreadPoolExecutor.AbortPolicy()  // 拒绝策略
        );

        // 提交6个任务（2核心线程 + 2队列 + 2临时线程 → 第7个任务触发拒绝）
        for (int i = 0; i < 7; i++) {
            try {
                executor.execute(() -> {
                    try {
                        Thread.sleep(1000);
                        System.out.println("任务执行: " + Thread.currentThread().getName());
                    } catch (InterruptedException e) {
                        e.printStackTrace();
                    }
                });
            } catch (RejectedExecutionException e) {
                System.err.println("任务被拒绝: " + e.getMessage());
            }
        }

        executor.shutdown();
    }
}
```

### **三、策略详解与应用场景**

#### **1. AbortPolicy（默认策略）**
- **行为**：抛出 `RejectedExecutionException`。
- **场景**：需要显式处理溢出的关键任务（如支付交易）。
- **Java 示例**：
  ```java
  new ThreadPoolExecutor.AbortPolicy()
  ```

#### **2. DiscardPolicy**
- **行为**：静默丢弃新任务。
- **场景**：非关键任务（如埋点数据上报）。
- **Java 示例**：
  ```java
  new ThreadPoolExecutor.DiscardPolicy()
  ```

#### **3. DiscardOldestPolicy**
- **行为**：丢弃队列头部的旧任务，重试提交新任务。
- **场景**：实时数据处理（如股票价格更新，旧数据可覆盖）。
- **Java 示例**：
  ```java
  new ThreadPoolExecutor.DiscardOldestPolicy()
  ```

#### **4. CallerRunsPolicy**
- **行为**：由提交任务的线程直接执行。
- **场景**：限流或避免任务丢失（如文件导出服务）。
- **Java 示例**：
  ```java
  new ThreadPoolExecutor.CallerRunsPolicy()
  ```

#### **5. 自定义策略**
- **行为**：实现 `RejectedExecutionHandler` 接口。
- **场景**：任务持久化或降级（如将任务存入数据库稍后重试）。
- **Java 示例**：
  ```java
  new RejectedExecutionHandler() {
      @Override
      public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
          System.out.println("自定义处理: " + r);
          // 例如：将任务保存到数据库
      }
  }
  ```

### **四、如何选择拒绝策略？**
| **场景需求**                | **推荐策略**            | **理由**                                                                 |
|----------------------------|------------------------|-------------------------------------------------------------------------|
| 关键任务不允许丢失          | `AbortPolicy`          | 显式抛出异常，让调用者处理。                                             |
| 非关键任务可容忍丢失        | `DiscardPolicy`        | 避免因任务堆积导致内存溢出。                                             |
| 优先处理最新任务            | `DiscardOldestPolicy`  | 确保系统实时性。                                                         |
| 需要限流或平滑降级          | `CallerRunsPolicy`     | 利用提交线程执行任务，自然限流。                                         |
| 需要特殊逻辑（如持久化）    | 自定义策略              | 灵活适应业务需求。                                                       |

---

### **五、总结**
- **线程池满时的行为**由拒绝策略决定，需根据业务特点选择。
- **Python** 需手动模拟拒绝逻辑，**Java** 直接支持策略配置。
- 生产环境中建议结合监控（如队列大小、拒绝次数）动态调整线程池参数。
