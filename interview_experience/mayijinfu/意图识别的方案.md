在大模型应用开发中，**用户意图识别（Intent Classification）** 是对话系统、智能客服、RAG 检索增强、任务型机器人等场景的核心环节。下面我从**工程实践**和**面试可直接回答**的角度，给出一套完整、可落地的方案，包含**技术选型、实现流程、优化策略**和**常见坑**。

---

## 一、核心思路：意图识别的本质
意图识别本质是**文本分类任务**，目标是将用户输入映射到预定义的意图标签（如：查询、反馈、投诉、预约、闲聊、拒绝、确认等）。
在大模型时代，主要有两条技术路线：
1. **传统/轻量方案**：规则 + 小模型（FastText、TextCNN、BERT 微调）
2. **大模型方案**：Prompt 工程 + 零样本/少样本分类 + 大模型 API（GPT、文心一言、通义千问等）

实际项目中通常是**混合方案**：规则兜底 + 大模型兜底 + 小模型做高并发、低延迟场景。

## 二、完整实现流程（面试可直接复述）
### 1. 需求分析与意图体系设计
- **梳理业务场景**：明确用户可能的问题类型（如：售后、物流、产品咨询、价格、活动、投诉、建议、闲聊等）。
- **定义意图标签体系**：
  - 一级意图：查询、反馈、投诉、预约、闲聊、拒绝、确认等
  - 二级意图：如“查询→物流查询→订单物流”“反馈→产品问题→质量问题”
  - 原则：**互斥 + 覆盖 + 可扩展**，避免标签重叠、模糊。
- **标注样本**：收集真实用户日志，人工标注意图，形成训练/测试集（至少几百到几千条，视业务复杂度）。

### 2. 方案选型（根据业务场景选择）
#### 方案 A：规则 + 关键词匹配（快速上线、低成本）
- **适用**：意图少、句式固定、上线急的场景（如 FAQ 机器人）。
- **实现**：
  - 构建**关键词/正则库**：如“物流”“订单”“退款”“投诉”“多少钱”“怎么用”等。
  - 匹配策略：
    - 精确匹配 + 模糊匹配（同义词、近义词）
    - 权重打分：关键词出现次数、位置、上下文
  - **优点**：0 训练成本、可解释性强、延迟极低。
  - **缺点**：泛化差，无法处理口语化、歧义、新表达。

#### 方案 B：小模型微调（高并发、低延迟、成本可控）
- **适用**：意图多、用户量大、需要稳定服务的场景（如智能客服、电商机器人）。
- **技术栈**：
  - 轻量模型：FastText（速度最快）、TextCNN/TextRNN（中等）、BERT/RoBERTa 微调（效果最好）
  - 框架：PyTorch/TensorFlow + Hugging Face Transformers
- **流程**：
  1. 数据预处理：分词、去停用词、文本清洗、长度截断
  2. 模型选择：
     - 追求速度：FastText（适合 100+ 意图，百万级样本）
     - 追求效果：BERT-base 微调（适合 50+ 意图，几千~几万样本）
  3. 训练与评估：
     - 指标：**准确率、精确率、召回率、F1**（尤其关注低样本意图的召回）
     - 交叉验证、分层采样（解决类别不平衡）
  4. 部署：ONNX/TensorRT 量化 + 模型服务（FastAPI/Triton），延迟可压到 **10ms 内**。
- **优点**：泛化能力强、成本低、可私有化部署。
- **缺点**：需要标注数据、迭代周期长。

#### 方案 C：大模型 Prompt 零样本/少样本分类（快速迭代、效果好）
- **适用**：意图频繁变化、标注数据少、需要快速上线的场景（如新产品上线、活动期）。
- **核心：Prompt 工程**
  - **零样本 Prompt 模板**（直接可用）：
    ```
    你是一个意图分类助手，请根据用户输入，判断其意图。
    可选意图：
    1. 产品咨询：询问产品功能、使用方法、参数等
    2. 物流查询：询问订单物流、发货时间、收货地址等
    3. 退款申请：申请退款、取消订单
    4. 投诉反馈：对产品/服务不满，要求处理
    5. 闲聊：无明确业务需求，如“你好”“在吗”“谢谢”
    6. 其他：不属于以上意图

    用户输入：{user_query}
    请只输出意图编号和名称，如：3. 退款申请
    ```
  - **少样本 Prompt**（加入示例，提升效果）：
    ```
    示例1：
    用户：我的订单什么时候到？
    意图：2. 物流查询

    示例2：
    用户：这个产品怎么用？
    意图：1. 产品咨询

    现在判断：
    用户：{user_query}
    意图：
    ```
- **优化**：
  - 意图描述要**具体、可区分**，避免模糊。
  - 对长文本做**摘要**后再分类，减少 Token 消耗。
  - 加入**约束**：“只输出意图，不要解释”，提升稳定性。
- **优点**：无需训练、泛化极强、支持动态意图、快速迭代。
- **缺点**：成本高（API 调用费）、延迟高（几百 ms）、不可控（ hallucination）。

#### 方案 D：混合方案（工程最佳实践）
**规则兜底 + 小模型主分类 + 大模型兜底**
- 流程：
  1. **规则层**：高置信度意图（如“退款”“投诉”）直接返回，减少后续压力。
  2. **小模型层**：对大部分输入做快速分类，返回高置信度结果（如置信度 > 0.8）。
  3. **大模型层**：对低置信度（0.5~0.8）、模糊、新表达的输入，调用大模型做最终判断。
  4. **反馈闭环**：将大模型判断结果、人工修正结果，回流到小模型训练集，持续迭代。

## 三、关键技术与优化策略（面试加分项）
### 1. 解决类别不平衡
- 问题：部分意图（如投诉）样本少，导致模型召回低。
- 方案：
  - **过采样**：复制少数类样本（注意避免过拟合）
  - **欠采样**：随机删除多数类样本
  - **加权损失**：`class_weight` 或 `focal loss`
  - **数据增强**：同义词替换、回译（中→英→中）、随机插入/删除词

### 2. 提升泛化能力
- **同义词/近义词库**：如“退款”→“退货”“取消订单”“退钱”
- **实体识别辅助**：先识别实体（订单号、产品名、时间），再结合实体判断意图（如“我的{订单号}怎么还没到？”→物流查询）
- **上下文建模**：对话历史 + 当前输入，共同判断（如用户先问“多少钱”，再问“怎么买”，意图是购买咨询）

### 3. 置信度与拒识
- 对模型输出的概率/置信度设置阈值：
  - 高置信度：直接返回意图
  - 中置信度：人工复核或大模型二次判断
  - 低置信度：拒识，返回“我没理解你的意思，请换个方式问”
- 避免模型强行分类到错误意图。

### 4. 意图分层与多标签
- **分层意图**：先分一级意图，再分二级意图（如先判断“查询”，再判断“物流查询/产品查询”），降低分类难度。
- **多标签意图**：用户输入可能包含多个意图（如“这个产品多少钱，怎么退款？”→产品咨询 + 退款申请），需支持多标签分类。

### 5. 工程落地优化
- **缓存**：对高频问题（如“多少钱”“怎么用”）做缓存，避免重复计算。
- **批处理**：对批量请求做批处理，提升吞吐量。
- **模型量化**：INT8/FP16 量化，减少模型体积，提升推理速度。
- **监控**：监控意图分布、置信度分布、错误率，及时发现意图漂移（如活动期出现新意图）。

## 四、常见面试问题与回答（直接背诵）
### Q1：大模型时代，为什么还要用小模型做意图识别？
**回答**：
大模型虽然泛化强，但存在**成本高、延迟高、不可控**的问题。小模型（如 BERT 微调、FastText）具有**低延迟（10ms 内）、低成本、可私有化部署、高并发**的优势，适合**核心业务、高流量场景**。实际项目中通常是**混合架构**：小模型做主分类，大模型做兜底和复杂意图处理，兼顾效果与成本。

### Q2：如何处理用户输入的歧义？
**回答**：
1. **上下文建模**：结合对话历史，消除歧义（如“它”“这个”指代前文的产品/订单）。
2. **多轮澄清**：对模糊输入，主动追问（如“你是想查询物流还是退款？”）。
3. **置信度阈值**：低置信度结果不直接返回，而是人工复核或大模型二次判断。
4. **实体识别**：先提取关键实体（订单号、产品名），再结合实体判断意图。

### Q3：如何评估意图识别模型的效果？
**回答**：
核心指标：
- **准确率**：整体分类正确的比例（适合类别平衡）。
- **精确率/召回率/F1**：关注少数类（如投诉）的召回率，避免漏判。
- **混淆矩阵**：分析模型容易混淆的意图，优化标签体系或样本。
- **业务指标**：意图识别准确率 → 对话成功率、人工转接率、用户满意度。

### Q4：如何应对意图漂移（新意图、新表达）？
**回答**：
1. **数据回流**：收集用户新问题、人工修正结果，定期更新训练集。
2. **大模型兜底**：对新表达，大模型可快速识别，无需重新训练。
3. **意图体系动态扩展**：支持新增意图，无需重构模型。
4. **监控预警**：监控意图分布变化，及时发现新意图（如活动期出现“优惠券查询”）。

## 五、总结（面试一句话总结）
在项目中，我会根据**业务场景、数据量、成本、延迟要求**选择**混合方案**：
1. **规则层**：快速处理高置信度、句式固定的意图；
2. **小模型层**：对大部分输入做高效、低延迟的分类；
3. **大模型层**：兜底处理模糊、新表达、复杂意图；
4. **通过数据回流、置信度控制、上下文建模**，持续优化意图识别效果，同时兼顾**效果、成本、延迟**三大核心指标。
